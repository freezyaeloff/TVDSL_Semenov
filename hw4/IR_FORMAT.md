# Промежуточное представление Funny для генерации кода

Формат — JSON в кодировке UTF-8. Версия — `funny.ir.v1`. Пример для функции, которая прибавляет единицу к параметру, взят из `hw3/examples/basic.funny`.

```json
{
  "schema_version": "funny.ir.v1",
  "functions": {
    "f": {
      "params": ["v2"],
      "returns": ["v3"],
      "types": {"v2": "int", "v3": "int", "t0": "int"},
      "blocks": {
        "B0": [
          {"op": "+", "args": ["v2", 1], "dest": "t0"},
          {"op": "mov", "args": ["t0"], "dest": "v3"},
          {"op": "ret", "args": ["v3"]}
        ]
      }
    }
  }
}
```

## Операнды и блоки

- Числа и логические значения JSON — литералы. Строка в `args` обозначает имя регистра.
- `vN` соответствует переменной с `symbol_id = N` из HW3. При затенении объявлений номера различаются. `tN` — временная внутри функции. Присваивания в один регистр допустимы несколько раз.
- `params` и `returns` сохраняют порядок имён из заголовка Funny. Таблица `types` задаёт тип каждого регистра в формате HW3, включая `bool`, `int`, массивы, `unit` и кортежи.
- `blocks` сопоставляет метки со списками инструкций. Вход функции — `B0`. Последняя инструкция блока всегда `jmp`, `br` или `ret`. Все переходы явные, поэтому порядок ключей в JSON можно менять.
- У инструкции всегда есть `op` и список `args`. Поле `dest` обозначает приёмник значения, `targets` — метки этой функции, `callee` — имя вызываемой функции. Операнды читаются до записи в `dest`.

## Инструкции

| `op` | `args` | Действие |
| --- | --- | --- |
| `mov` | `[a]` | Скопировать значение в `dest` |
| `+`, `-`, `*`, `/` | `[a,b]` | Целочисленная арифметика |
| `neg`, `not` | `[a]` | Смена знака или логическое отрицание |
| `<`, `<=`, `>`, `>=`, `==`, `!=` | `[a,b]` | Сравнение с результатом `bool` |
| `length`, `index` | `[a]`, `[a,i]` | Длина массива или чтение элемента |
| `update` | `[a,i,x]` | Получить копию массива с новым элементом по индексу `i` |
| `call` | аргументы по порядку | Вызвать `callee` и записать результат в `dest` |
| `requires`, `ensures`, `invariant`, `assert`, `assume` | `[p]` | Проверить логическое условие |
| `jmp` | `[]` | Перейти на `targets[0]` |
| `br` | `[p]` | При истине перейти на `targets[0]`, при лжи на `targets[1]` |
| `ret` | значения по порядку | Вернуть ноль, одно или несколько значений |

## Семантика выполнения

Для будущего генератора JVM выбран знаковый 32-битный `int`. Целые литералы и результаты арифметики приводятся по модулю 2³². Деление округляется к нулю. Деление на ноль и обращение к индексу вне диапазона `0 <= i < length(a)` завершают выполнение с ошибкой.

Выражения и аргументы вызовов вычисляются слева направо. У `and` и `or` правая часть выполняется только тогда, когда результат ещё зависит от неё. В IR это выражено через `br` и запись результата в одну временную на обоих путях.

Каждый вызов получает собственные регистры. При выходе `ret` возвращает значения именованных результатов. Пустой список соответствует `unit`, один элемент — самому значению, несколько элементов — кортежу. В проверочном интерпретаторе `unit` представлен как `()`.

Предусловия проверяются при входе, постусловия — перед возвратом. Инварианты проверяются в заголовке цикла перед каждой проверкой условия, включая последнюю. Пустые контракты пропускаются. Проверочный интерпретатор останавливается на ложном предикате, в том числе на `assume`.

## API

```python
from hw3.funny_types import check
from hw4.ir import generate
from hw4.optimize import optimize
from hw4.flow import analyze
from hw4.interpreter import run

source = "function f(x: int) returns (r: int) { r = x + 1; }"
before = generate(check(source))
after = optimize(before, constants=True, algebra=True, dce=True)
info = analyze(after["functions"]["f"])
assert run(after, "f", [4]) == 5
```

`generate` принимает аннотированный AST версии `funny.typed-ast.v1` без ошибок. `optimize` возвращает отдельную копию программы. Аргументы `run` задаются в порядке `params` и должны соответствовать типам функции.

`analyze` возвращает `cfg` (преемники блоков), `conflicts` (соседи временных), `colors` (имя временной → номер цвета) и `metrics`. При генерации кода именованным переменным можно выделить отдельные локальные слоты. Для `tN` номер слота тогда равен первому свободному слоту после переменных плюс `colors["tN"]`. Номера цветов начинаются с нуля и действуют в пределах одной функции. Выбор инструкции загрузки и записи определяется по `types`.

В JSON командной строки обе стадии находятся в `before` и `after`. Каждая содержит `ir` в описанном формате и `analysis` с результатом `analyze` для каждой функции. Для передачи оптимизированной программы следующему этапу используется `after.ir`.

В `metrics` входят `blocks` (число состояний CFG), `instructions`, `temporaries` и `colors`.
