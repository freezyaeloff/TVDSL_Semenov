# HW2 — синтаксический анализатор Funny

Парсер на Python 3.10+ без сторонних библиотек: рекурсивный спуск на основе LL(1)-грамматики, AST в JSON, диагностика с номерами строк и колонок, восстановление после синтаксических ошибок в инструкциях.

## Файлы

Все файлы проекта находятся в одной папке:

```text
hw2/
    README.md
    funny_parser.py
    test_parser.py
    grammar.ebnf
    dfa.json
    expected_basic.json
    demo.funny
    errors.funny
    tests.md
```

- `funny_parser.py` — лексический анализ через детерминированный конечный автомат (ДКА), рекурсивный спуск, построение AST и интерфейс командной строки.
- `dfa.json` — таблица переходов ДКА, необходимая для работы лексера.
- `grammar.ebnf` — описание используемой грамматики и приоритетов операторов.
- `test_parser.py` — позитивные, негативные и интеграционные тесты, включая сравнение AST с эталоном.
- `expected_basic.json` — эталонный JSON AST для простейшей функции.
- `demo.funny` — пример программы с массивами, условиями, циклом и контрактами.
- `errors.funny` — пример с двумя синтаксическими ошибками для демонстрации восстановления.
- `tests.md` — автоматически создаваемый отчёт о тестировании.

## Запуск

Требуется Python 3.10 или новее. Устанавливать сторонние библиотеки не нужно.

Из папки `hw2`:

```bash
python funny_parser.py demo.funny
```

Сохранение AST в файл:

```bash
python funny_parser.py demo.funny --out result.json
```

Проверка обработки ошибок:

```bash
python funny_parser.py errors.funny
```

На Windows команда Python может называться `py`, на Linux/macOS — `python3`. В примерах ниже при необходимости замените `python` на подходящую команду.

AST выводится в stdout, диагностика — в stderr в формате `строка:колонка: сообщение`. При наличии ошибок программа завершает работу с кодом 1. При использовании `--out` AST сохраняется в указанный файл; при синтаксических ошибках сохраняется частичное дерево, если лексический анализ завершён.

`dfa.json` загружается относительно расположения `funny_parser.py`. Пути входного файла и `--out` задаются относительно текущей папки. Родительская папка выходного файла должна существовать.

## Архитектура

1. **Лексер** использует 128 ASCII-переходов каждого состояния из `dfa.json`. Сканирование выполняется по принципу maximal munch: сохраняется последнее принимающее состояние, чтобы выбрать самый длинный подходящий токен. Пробелы и однострочные `//`-комментарии пропускаются. Для токенов сохраняются тип, исходный текст, строка и колонка с единицы. В конец потока добавляется `EOF`.
2. **Парсер** выбирает правило разбора по текущему токену. Объявления функций, блоки, инструкции и выражения разбираются отдельными функциями рекурсивного спуска. Приоритеты выражений реализованы разбором по уровням, описанным в `grammar.ebnf`.
3. **AST** состоит из обычных словарей с полями `type`, `line`, `column` и дополнительными полями конкретного узла. Дерево сериализуется в JSON для дальнейшей обработки.
4. **Обработка ошибок:** `expect()` сообщает позицию и ожидаемый символ. Внутри блока восстановление в режиме паники пропускает ошибочную инструкцию до `;` или `}` и продолжает разбор. При ошибке в заголовке или незакрытом блоке парсер может восстановиться на следующем `function`. Каждая попытка восстановления продвигает позицию в потоке токенов либо завершает разбор текущего блока.

### Поддерживаемые конструкции

- Функции вида `function name(x, y) returns (result)` с необязательным `uses (tmp)`.
- Необязательные повторяющиеся контракты `requires expr;` и `ensures expr;`, включая пустые `requires;` и `ensures;`.
- Присваивания, блоки `{ ... }`, условия `if (...) { ... } else { ... }` и цепочки `else if`.
- Циклы `while (...) invariant expr; { ... }` с необязательными инвариантами.
- Инструкции `assert expr;` и `assume expr;`.
- Индексация `a[i]`, присваивание `a[i] = expr;`, вызовы `f(x)` и `length(a)` внутри выражений.
- Целые числа, `true`, `false`, `not`, унарный минус, арифметические операторы `* / + -`, сравнения, `and` и `or`.

### Присваивание элементу массива

Конструкция `a[i] = x;` преобразуется в присваивание результата функционального обновления массива:

```text
Assign(target="a", value=ArrayUpdate(array=Name("a"), index=Name("i"), value=Name("x")))
```

Это преобразование структуры AST. Парсер не копирует массив при разборе: интерпретация узла `ArrayUpdate` относится к следующим этапам обработки программы.

## Допущения и ограничения

Реализация использует подъязык, описанный в `grammar.ebnf`. В исходных материалах указан `HW02_parsing.md`, но отсутствуют `docs/funny.ru.md` и слайды P03/P04, поэтому соответствие полной грамматике Funny по этим материалам не установлено.

- Параметры и результаты функций задаются именами без аннотаций типов. Двоеточие не поддерживается таблицей ДКА.
- Слова `requires` и `ensures` сначала распознаются как `IDENT`, затем при полном совпадении текста преобразуются в `REQUIRES` и `ENSURES`. Использовать их как имена нельзя.
- Контракты располагаются после заголовка функции перед `{` и заканчиваются `;`. Инварианты располагаются между условием цикла и `{`.
- `=` обозначает присваивание, `==` — сравнение. Строки, вещественные числа, типы, объявления переменных, `return`, `for` и самостоятельные вызовы функций в качестве инструкций не поддерживаются.
- В левой части присваивания поддерживаются `x = ...` и один уровень индексации `a[i] = ...`. Присваивание `a[i][j] = ...` не реализовано. В выражениях индексация может быть вложенной.
- Входной алфавит — ASCII. Не-ASCII символы, включая кириллицу в комментариях, вызывают лексическую ошибку. Примеры используют только ASCII.
- После синтаксических ошибок внутри блоков парсер пытается продолжить разбор. При лексической ошибке выполнение прерывается.

## Приоритеты операторов

От слабого к сильному:

```text
or
and
== !=
< <= > >=
+ -
* /
унарные not, -
постфиксные вызовы f(...) и индексация a[...]
```

Бинарные операторы левоассоциативны, префиксные унарные — правоассоциативны. Скобки меняют порядок группировки выражений.

### Что проверяется

- **Позитивные сценарии:** объявления и контракты функций, `uses`, базовые инструкции, циклы и инварианты, `if/else if/else`, массивы, приоритеты, унарные операции, вызовы, комментарии, несколько функций, разбор `demo.funny`, сравнение AST с `expected_basic.json`.
- **Негативные сценарии:** пустой ввод, незакрытые `(`, `[` и `{`, неправильный оператор, лишние токены, пропущенное выражение, неизвестный символ, несколько ошибок подряд, восстановление до следующей функции, обработка 300 ошибочных инструкций без зависания.
- **Интеграционные сценарии:** координаты и значения токенов, maximal munch, ключевые слова, переводы строк Windows, отклонение не-ASCII символов.
- **Командная строка:** JSON в консоли, запись AST при запуске из другой папки, код завершения 1 и частичное AST на ошибочном примере.

По данным исходного описания, проект проверен на Python 3.12.14: 30 тестов, включая 3 проверки запуска из командной строки.
