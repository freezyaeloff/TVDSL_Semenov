# HW3 — семантические проверки и типы Funny

Семантический анализатор на Python 3.10+ без сторонних библиотек. Использует ДКА, парсер и AST из HW2; добавляет аннотации типов, таблицы символов, проверку имён и типов, диагностику с позициями и вывод типов локальных переменных.

## Запуск

Из корня репозитория:

```bash
python hw3/funny_types.py hw3/examples/demo.funny
python hw3/funny_types.py hw3/examples/demo.funny --out typed_ast.json
python hw3/funny_types.py hw3/examples/errors.funny --out errors.json
python hw3/test_types.py
```

Также из корня доступны пакетный запуск и импорт из Python:

```bash
python -m hw3.funny_types hw3/examples/demo.funny
python -m unittest hw3.test_types -v
```

`hw2` и `hw3` — Python-пакеты с `__init__.py`. Импорт парсера записан явно:
`from hw2.funny_parser import ...`; модули HW3 импортируются через `hw3`.
В PyCharm открывайте корень `TVDSL_Semenov`, содержащий обе папки.
Ручная настройка `PYTHONPATH` и Sources Root для `hw2` не требуется.

Из папки `hw3`: `python funny_types.py examples/demo.funny` и `python test_types.py`. Для чтения программы из stdin вместо пути укажите `-`. На Windows команда может называться `py`, на Linux/macOS — `python3`. Для UTF-8 в перенаправленных потоках на Windows можно использовать `python -X utf8`.

Без `--out` JSON с полями `schema_version`, `ast`, `symbols`, `errors` выводится в stdout; с `--out` сохраняется в файл. Родительская папка выходного файла должна существовать. Диагностика дополнительно печатается в stderr, например: `4:11: E_TYPE_MISMATCH: левый операнд '+': ожидался int, получен bool`.

Коды завершения: `0` — ошибок нет; `1` — ошибки лексики, синтаксиса или семантики; `2` — ошибка ввода/вывода либо аргументов CLI. HW2 и ДКА загружаются относительно исходников; входной и выходной пути — относительно текущей папки.

## Поддерживаемые конструкции и типы

Сохраняются функции, именованные результаты, `uses`, присваивания, массивы, блоки, `if/else if/else`, `while`, инварианты, `assert`, `assume`, `requires` и `ensures` из HW2. Пустые контракты остаются допустимыми. Добавлены аннотации `: Type` и локальные объявления `let`, позволяющие проверять области видимости во вложенных блоках.

```text
function inc(x: int) returns (r: int) {
    r = x + 1;
}

function example(a: int[], flag: bool) returns (r: int) uses (tmp) {
    tmp = length(a);           
    let value: int;
    if (flag) {
        value = inc(tmp);
    } else {
        value = 0;
    }
    r = value;
}
```

Выбрано подмножество с `int`, `bool` и однородными массивами `T[]`, включая вложенные. Параметры и каждый именованный результат требуют явного типа. В `uses` и `let` аннотация необязательна. `return` не вводится: результаты задаются присваиваниями именам из `returns`, как в HW2.

| Операция | Правило |
| --- | --- |
| `+ - * /`, унарный `-` | Операнды и результат `int` |
| `< <= > >=` | Два `int`, результат `bool` |
| `and or not` | Операнды и результат `bool` |
| `== !=` | Два одинаковых простых типа: `int` либо `bool`; результат `bool` |
| `a[i]` | Массив `T[]`, индекс `int`, результат `T` |
| `a[i] = x` | Тип `x` совпадает с типом элемента; сохраняется `ArrayUpdate` из HW2 |
| `length(a)` | Один массив любого типа элементов, результат `int` |
| Вызов функции | Проверяются имя, число аргументов и их типы по сигнатуре |
| Присваивание | Тип правой части унифицируется с типом цели |
| Условия и контракты | Тип `bool` |

Функции вызываются внутри выражений: `r = inc(x);`. Их сигнатуры хранятся как служебный тип `func`. Передача функций как значений и самостоятельные инструкции вызова не поддерживаются. Списки результатов HW2 сохранены: без результатов вызов имеет служебный тип `unit`, с несколькими — `tuple`. Эти типы описаны в формате AST и могут выводиться для локальных переменных из вызова; синтаксиса их аннотаций, литералов и распаковки нет.

## Имена, вывод типов и инициализация

- Сигнатуры функций регистрируются до проверки тел; разрешены рекурсия и вызовы функций, объявленных ниже.
- Параметры, результаты, `uses` и `let` в основном теле принадлежат одной области функции. Повторное объявление в ней — ошибка. Вложенный блок создаёт новую область; затенение разрешено. Внутренние имена не выходят за пределы блока.
- Локальную переменную нужно объявить до использования. Присваивание неизвестному имени не создаёт переменную. Ссылки связываются с объявлениями через `symbol_id`.
- Для переменной без аннотации первое корректное присваивание в порядке обхода исходника определяет тип. Противоречие типов или отсутствие корректного присваивания — ошибка. Ошибочная правая часть не определяет тип и не инициализирует переменную.
- Параметры инициализированы при входе; результаты и локальные переменные — после корректного присваивания. `let x = x;` вызывает ошибку чтения до присваивания.
- После `if` гарантируются только присваивания из обеих ветвей. Без `else` учитывается путь без выполнения тела. Новые присваивания в `while` не гарантируются после цикла.
- Каждый именованный результат должен быть присвоен на всех путях. `requires` проверяется до тела, `ensures` — после. Повторная ошибка чтения неприсвоенного результата в `ensures` подавляется.

## Диагностика

Ошибки содержат фазу, код, строку, колонку с единицы и описание на русском языке. За проход собирается несколько ошибок. Неверное выражение получает тип `error`, подавляющий производные несовместимости.

Основные коды: `E_UNKNOWN_NAME`, `E_DUPLICATE`, `E_UNINITIALIZED`, `E_ANNOTATION_REQUIRED`, `E_TYPE_UNKNOWN`, `E_TYPE_MISMATCH`, `E_ARGUMENT_COUNT`, `E_NOT_CALLABLE`, `E_NOT_ARRAY`, `E_EQUALITY_TYPE`, `E_ASSIGN_FUNCTION`, `E_FUNCTION_VALUE`, `E_BUILTIN_VALUE`, `E_CANNOT_INFER`, `E_RESULT_UNASSIGNED`. Лексика и синтаксис обозначаются `E_LEXICAL` и `E_SYNTAX`.

При восстановимых синтаксических ошибках анализируется частичное дерево. При лексической ошибке разбор прерывается, `ast` равен `null`, а JSON содержит диагностику.

## Тестирование и ограничения

`test_types.py` проверяет корректные и ошибочные программы, области видимости, типы, сигнатуры, массивы, контракты, унификацию, бонусный вывод типов, точные позиции, эталон AST и CLI. Ожидаемые ошибки записаны в `examples/errors.expected.json`, полное эталонное дерево — в `examples/basic.expected.json`.

Регрессионные тесты HW2: `python -m unittest discover -s hw2 -p test_parser.py -v`.

Строки, float, перегрузки, неявные приведения и пользовательский полиморфизм не реализованы. Сохраняются ASCII-алфавит исходных программ и ограничения HW2 на литералы массивов и запись `a[i][j] = value`. Поток проверяется консервативно, без доказательства константных условий и завершения циклов. Проверяется тип контрактов, а не их истинность; границы массивов и деление на ноль относятся к выполнению. Глубина разбора ограничена стеком Python.

Описание дерева: [AST_FORMAT.md](AST_FORMAT.md). Краткий отчёт: [report.md](report.md).
