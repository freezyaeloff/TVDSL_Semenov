# Аннотированный AST Funny для HW4

Формат — JSON, кодировка UTF-8. Версия контракта: `funny.typed-ast.v1`. При несовместимом изменении структуры нужно изменить версию.

```json
{
  "schema_version": "funny.typed-ast.v1",
  "ast": {"type": "Program", "line": 1, "column": 1, "functions": []},
  "symbols": [],
  "errors": []
}
```

## Связь с HW2

Сохраняются поля `type`, `line`, `column` и структура узлов HW2. Поле `type` по-прежнему обозначает вид узла; семантический тип выражения записывается отдельно в `inferred_type`. `line` и `column` начинаются с единицы.

Используются исходные выражения HW2: `Int`, `Bool`, `Name`, `Unary`, `Binary`, `Call`, `Index`, `ArrayUpdate`. Семантический проход не заменяет их другими видами узлов. Каждое такое выражение в дереве после анализа содержит `inferred_type`, включая ошибочные выражения.

Пример:

```json
{
  "type": "Binary",
  "line": 2,
  "column": 11,
  "operator": "+",
  "left": {
    "type": "Name", "line": 2, "column": 9,
    "name": "x", "symbol_id": 2, "inferred_type": "int"
  },
  "right": {
    "type": "Int", "line": 2, "column": 13,
    "value": 1, "inferred_type": "int"
  },
  "inferred_type": "int"
}
```

## Представление типов

| Семантический тип | JSON |
| --- | --- |
| int, bool, unit | `"int"`, `"bool"`, `"unit"` |
| Ошибочный / невыведенный | `"error"` |
| Массив T | `{"kind":"array","element":T}` |
| Функция | `{"kind":"func","params":[T1,T2],"returns":R}` |
| Кортеж | `{"kind":"tuple","items":[T1,T2]}` |

`T`, `T1`, `T2` и `R` рекурсивно используют тот же формат. Один результат функции представлен своим типом; ноль — `unit`; два и более — кортежем. Типы `func`, `unit` и `tuple` служат для описания сигнатур и результатов вызовов HW2; пользовательских аннотаций этих типов нет. Неразрешённых переменных унификации в JSON нет. В ошибочной программе составной тип может содержать `error` в компоненте.

Встроенный символ `length` в таблице символов имеет специальное значение `value_type: "builtin length(array<T>):int"`. Это схема встроенной операции, не тип пользовательского значения. В каждом корректном вызове `length` выражение-имя получает конкретную специализацию, например `{"kind":"func","params":[{"kind":"array","element":"bool"}],"returns":"int"}`.

## Объявления и связывание имён

Узел `Function` сохраняет списки строк `params`, `returns`, `uses`, контракты и тело HW2. Добавлены:

- `name_position`: позиция идентификатора функции;
- `declarations`: объект с массивами `params`, `returns`, `uses` из узлов `Declaration`;
- `signature`: структурный тип функции;
- `symbol_id`: идентификатор глобального символа функции;
- `scope_id`: идентификатор области функции.

`Declaration` содержит `name`, `annotation`, `declared_type`, `symbol_id`, `line`, `column`. `annotation` — исходное синтаксическое дерево аннотации либо `null`. Виды узлов аннотации: `TypeName(name)` и `ArrayType(element)`. `declared_type` содержит итоговый семантический тип, в том числе выведенный для локальных переменных.

Новый узел `VarDecl` содержит те же поля, что `Declaration`, а также `value` — инициализатор или `null`. Позиция указывает на имя переменной.

`Name.symbol_id` связывает чтение с объявлением. `Assign.symbol_id` связывает цель присваивания с объявлением. У каждого `Block` есть `scope_id`; основное тело и заголовок функции используют одну область, вложенные блоки — собственные. У ошибочных неизвестных имён и повторных объявлений `symbol_id` может отсутствовать.

Каждая запись `symbols` имеет поля:

```json
{
  "id": 2,
  "name": "x",
  "kind": "parameter",
  "scope_id": 1,
  "line": 1,
  "column": 12,
  "value_type": "int"
}
```

Виды символов: `builtin`, `function`, `parameter`, `result`, `local`. Идентификаторы уникальны внутри одного результата анализа и детерминированы порядком объявления; они не служат постоянными ID между версиями программы. Затенённые имена имеют разные ID. Таблица включает локальные символы завершённых областей, чтобы HW4 мог разрешать ссылки без повторного обхода областей.

## Ошибки и дальнейшая обработка

```json
{
  "phase": "semantic",
  "code": "E_TYPE_MISMATCH",
  "line": 4,
  "column": 11,
  "message": "левый операнд '+': ожидался int, получен bool"
}
```

`phase`: `lexical`, `syntax` или `semantic`. Коды приведены в README. Синтаксические ошибки идут перед семантическими; внутри семантического прохода порядок определяется обходом и финальными проверками. Диагностика не сортируется по позиции: например, сообщение о неприсвоенном результате указывает на заголовок, но формируется после проверки тела.

При восстановимой синтаксической ошибке `ast` содержит частичное дерево с аннотациями для сохранившихся выражений. При лексической ошибке `ast` равен `null`, `symbols` пуст. Ошибки типов не удаляют узлы дерева.

HW4 должен начинать генерацию IR только при `errors == []` и ненулевом `ast`. Тогда каждый тип выражения конкретен и не содержит `error`, а все разрешаемые имена имеют `symbol_id`. Типы следует читать из `inferred_type` и `symbols`, а не выводить повторно. Для присваивания элементу массива сохраняется преобразование `a = ArrayUpdate(a, i, value)` из HW2.

Полный эталон входа и результата: `examples/basic.funny` и `examples/basic.expected.json`. Для получения дерева более крупного примера выполните `python hw3/funny_types.py hw3/examples/demo.funny --out typed_ast.json` из корня репозитория.
