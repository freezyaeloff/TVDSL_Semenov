# HW3. Краткий отчёт

## Реализация

HW3 продолжает Funny из HW1/HW2. `funny_frontend.Parser` наследует парсер HW2: разбор выражений, блоков, условий, циклов и преобразование записи элемента массива сохранены. Расширены заголовки функций и добавлены локальные объявления `let` для проверки вложенных областей видимости. Лексер использует `hw2/dfa.json`, дополнительный разделитель `:` и ключевое слово `let`. Файлы HW1/HW2 не изменены.

Анализ регистрирует сигнатуры функций, проверяет тела и завершает вывод типов. Области связаны с родительскими областями; поиск имени идёт от внутренней к внешней. В одной области имя объявляется один раз. Чтения и цели присваиваний связаны с объявлениями через ID символов. Функции доступны во всей программе, локальные имена — после объявления.

## Типы и унификация

Для явных аннотаций выбрано подмножество `int`, `bool` и однородных массивов. Параметры и именованные результаты аннотируются обязательно. Арифметика требует `int`, логика — `bool`, индексы — `int`, условия и контракты — `bool`. Приведений и перегрузок нет.

Сигнатуры представлены служебным типом `func`; функции вызываются внутри выражений и не передаются как значения. Списки результатов HW2 сохранены: ноль результатов представлен типом `unit`, несколько — `tuple`. Пользовательского синтаксиса этих типов нет.

Унификация сопоставляет конструкторы типов и их компоненты. Неизвестный локальный тип представлен переменной унификации. Проверка вхождения исключает бесконечные типы; при неуспехе ограничения подстановки откатываются. Встроенная `length` получает свежую переменную типа элемента при каждом вызове. Пользовательские переменные мономорфны.

## Вывод локальных типов — бонус

В `uses (tmp)` и `let tmp;` тип определяется первым корректным присваиванием в порядке обхода исходника. После `tmp = 1;` тип равен `int`, а последующее `tmp = true;` вызывает ошибку. Неверная правая часть не определяет тип; последующее корректное присваивание может его определить. Если вывести тип не удалось, формируется диагностика.

Отдельно хранится множество гарантированно инициализированных символов. После `if` берётся пересечение состояний ветвей; новые присваивания в `while` не гарантируются после цикла. Это предотвращает чтение переменной с известным типом, но без гарантированного значения. Каждый именованный результат должен быть присвоен на всех путях.

## Диагностика и AST

Ошибки содержат код, фазу, строку, колонку и описание на русском языке. Анализ собирает независимые ошибки, проверяет аргументы даже при ошибочном вызове и подавляет каскадные несовместимости через тип `error`.

JSON сохраняет структуру HW2 и добавляет тип каждого выражения в `inferred_type`, таблицу символов и ссылки на объявления. Формат для HW4 описан в `AST_FORMAT.md`. Полный эталон дерева и ожидаемые ошибки включены в примеры.

## Проверка

Тесты проверяют имена, затенение, типы, сигнатуры, рекурсию, массивы, контракты, вывод локальных типов, накопление ошибок и CLI. Ошибочный пример сравнивается с ожидаемыми кодами и точными координатами, простая программа — с полным эталоном AST. Проверены также occurs check и откат подстановок при неуспехе унификации.

Результаты проверки на Python 3.12.14: 84 теста HW3 и 30 регрессионных тестов HW2 прошли.

## Ограничения

Подмножество не включает строки, float, перегрузки, приведения, пользовательский полиморфизм и функции как значения. Из новых конструкций оставлены только аннотации и `let`. Сохраняются ограничения HW2: ASCII в исходниках, отсутствие литералов массивов и присваивания `a[i][j] = value`.

Проверка потока консервативна: константные условия и завершение циклов не доказываются. Контракты проверяются по типам. Ошибки времени выполнения и доказательство корректности остаются следующим этапам.
